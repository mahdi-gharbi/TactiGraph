1. What the app is

TactiGraph AI is a football analytics workbench built around a simple idea: a conclusion should be traceable to its data and calculation. It combines interactive match analysis, statistical models, passing networks, descriptive playing-style research and a constrained analytical assistant.

It is a Data Science and Applied AI portfolio project as well as a working analysis tool. Its value is not merely a dashboard or a chatbot: it demonstrates ingestion, quality checks, chronological evaluation, reproducible experiments, model comparison and evidence-backed presentation in one system.

Choosing your league

Premier League preparation is complete: 380 matches, 20 teams, 644 players and 1,313,773 events, with all corpus integrity checks passing. Separate xG, xT, third-pass forecasts and four passing-style profiles are published locally. For third-pass forecasts, the graph experiment did not establish an advantage over the selected LightGBM baseline; the app serves that baseline and exposes the full comparison. Two negative source durations are recorded as quality warnings and unavailable normalized durations; the original files remain unchanged.

Use the league selector in the top bar to switch between the Women's Super League and men's Premier League 2015/16 (380 matches). Every match, audit, evidence request and model result then uses that league's separate database. Premier League has its own model versions; unavailable model panels mean training or publication has not completed. Open the Premier League workspace.

The Premier League chronological split has 228 training, 58 tuning, 37 calibration and 57 test matches, grouped by whole dates. Training ends 23 January 2016, tuning ends 5 March and calibration ends 10 April. This tests later matches in one season, not a future season. The research figures below describe the original WSL experiment; consult Experiments in the selected league for its actual results. The existing analyst benchmark and curated showcase concern WSL; a separate Premier League analyst benchmark and human-reviewed showcase have not been established.

The WSL dataset is a pinned snapshot of StatsBomb Open Data covering 457 FA Women's Super League matches across 2018/19, 2019/20, 2020/21 and 2023/24. It is historical, not a live feed, and does not cover all football competitions. Match dates and team/player names come from the source.

Typical questions include: Where did a team's shots occur? How did progression change between two periods? Which players exchanged passes? Was passing concentrated through a few players? How likely were particular shots or possession episodes to produce outcomes?

The app cannot establish a coach's intentions, reconstruct every off-ball movement, show tracking-based formations, guarantee a result or prove that a substitution caused a change.

3. Start the app and fix connection errors

Normal startup on this Windows PC

  1. Open C:\Users\Lenovo\Documents\ChatGPT\EuroSkill AI in File Explorer.
  2. Double-click Start-TactiGraph.cmd. It starts the existing local Python server and opens the app. If the server is already running in local mode, it reuses it.
  3. Open http://127.0.0.1:8003/. The guide is at http://127.0.0.1:8003/guide.

The launcher uses the existing environment, built frontend and research database. It does not reinstall dependencies, retrain models, reimport matches or deploy anything. Run it again after a PC restart. Startup is manual; there is no installed Windows service or automatic boot task.

Why “Failed to fetch” appeared

On 26 September, a direct check of port 8003 found no running server and a connection-refused response. The browser still displayed the previously loaded interface, but its API requests could no longer reach the backend. A browser tab is not the server itself.

Start the launcher, then refresh the tab or use Retry. The interface now gives a more useful message when its network request cannot reach the local server. A future connection failure could also involve a port conflict, firewall or another network problem; the message alone is not a complete diagnosis.

Manual fallback

cd "C:\Users\Lenovo\Documents\ChatGPT\EuroSkill AI"
.\.venv\Scripts\tactigraph.exe serve --host 127.0.0.1 --port 8003

Keep that terminal open while using the app. Stop that foreground server with Ctrl+C. For launcher startup errors, read output/local-server.stderr.log; normal server output goes to output/local-server.stdout.log.

Check /api/v1/health for server availability. A successful response includes status: ok and mode: local. The different /api/v1/ready endpoint is a public-release review gate: it intentionally returns 503 while human approval is pending. That 503 does not mean the local research app is broken.

Port 8002 is the isolated Docker/PostgreSQL public-mode rehearsal, if Docker and that stack are running. Older tabs on 8000 or 8001 may point to servers that are no longer running. Use 8003 for your normal local workspace.

4. Navigation and a first walkthrough

The main sections are Overview, Match Lab, Evidence Analyst, Experiments and Methodology. The application uses a horizontal navigation bar; narrow screens show its icons with accessible names.

  1. Start with Overview to see coverage and data quality.
  2. Open Match Lab, select a season and match, and examine the shot map and timeline. Arsenal WFC–Liverpool WFC, match 19717, is one available example.
  3. Filter to a team and the second half. Inspect a shot or the supporting evidence for a count.
  4. In Periods & passing networks, compare second-half 0–15 against 15–30 minutes. Read both measurements, then inspect their source references.
  5. Visit Evidence Analyst. Select Deterministic for a first guided report without any model service.
  6. Use Experiments to understand the models and their limitations before interpreting predictions.
Time convention: bounds are relative to the selected half. In the second half, 0–15 means match minutes 45–60; 15–30 means 60–75. Windows include the start and exclude the end. Do not enter 45–60 when you intend the first fifteen minutes of the second half.

5. Overview: understand the dataset

Overview presents source coverage, audit information and exploratory summaries. Use it to check what is actually ingested and whether quality warnings or exclusions exist before drawing a match-level conclusion.

Charts include event distributions, shot origins, temporal patterns, team profiles and players with recorded shots. The exploratory research summaries use the training portion to reduce leakage into later model evaluation.

The frozen chronological split contains 194 training, 89 tuning, 42 calibration and 132 test matches. Training covers 2018/19 and 2019/20; 2020/21 is split chronologically between tuning and calibration; 2023/24 supplies the historical test partition.

In the public rehearsal, only twelve selected matches are hosted. Stored aggregate research reports can still describe the original 457-match corpus. Do not confuse a model's original research sample with the number of matches in the demo database.

6. Match Lab: inspect a match

Match selection and shots

Use the season, search and match controls to find a fixture. The match summary shows recorded match information and stored model results. The shot map places eligible shots on the pitch, and the timeline helps connect shots to their time within the game.

  1. Choose Team, Period and, when useful, a player.
  2. Set start/end minutes for a period-local window.
  3. Compare the filtered count and visible shots. Missing locations can affect map coverage without removing shots from the underlying count.
  4. Click a shot marker or focus it and press Enter to open its evidence. Use Inspect evidence for the aggregate count.
  5. Read event IDs, timestamps, pinned source links and model provenance. Close the evidence panel with its button or Escape where supported.

An empty selection can be a valid zero result. An unavailable prediction is different from zero xG; the app should not replace missing model output with a fabricated number.

Compare periods and passing networks

Select the team, half and two chronological, non-overlapping windows. Run the comparison. Read shot counts, xG, pass volume/completion, entry rates, field tilt and signed movement xT, together with their units and denominators. Unequal window lengths can make raw totals misleading; use rates where provided.

The two directed networks summarize completed passes. Nodes represent players and arrows represent observed sender-to-recipient connections. Player locations are averages of on-ball actions, not actual positions throughout the match or a detected formation. Sparse windows can produce unstable networks.

Remove a player

Select a network player and choose Remove selected player from observed network. Compare connectivity, components and retained pass weight. Use Restore observed network to undo the view change. This removes a node and its edges from a fixed historical graph; it does not simulate substitutions, replacement behaviour or what the team would actually have done.

Trends, forecasts and styles

Trend displays show separate five-minute xG and signed-xT curves, match context and candidate changes. They are not a single control score or proof of a turning point's cause.

Will this episode produce a shot? lists stored forecasts made at the third completed pass of eligible open-play control episodes. Inspect the cutoff and model evidence. The serving predictor is LightGBM; a graph neural network was evaluated but did not beat it. Training-sample predictions are labelled and should not be treated as independent test performance.

Measured patterns of play assigns eligible 15-minute team windows to one of four passing profiles. Read each profile's measured averages, then inspect source passes for the window. These descriptive clusters use passing features; they are not definitive team identities or tactical labels. Stoppage time and incomplete/insufficient-data windows are excluded from this particular analysis.

7. Evidence Analyst and cached reports

Generate a local guided report

  1. Choose a match and open Evidence Analyst.
  2. Choose Deterministic for the simplest setup. No language model or external generation request is needed.
  3. Select the team and one of three guided questions: progression, chance creation or passing concentration.
  4. Select the half and valid before/after windows, then generate the report.
  5. Read the claims and qualifications. Open before/after evidence for a numerical statement. Expand verification details to see denominators, versions and limitations.

The optional question field accepts supported phrasings of the guided tasks. This is not unrestricted football chat. Unsupported requests, such as identifying an off-ball run from absent tracking, should be refused or qualified rather than answered with invented information.

Understand provider choices

  • Deterministic: analytical code calculates values and fixed templates express verified comparisons.
  • Groq · GPT-OSS 20B: requires a configured backend key and network access. The model selects supported claims; it does not invent their statistics or wording. The adapter can fall back to deterministic results.
  • Local Ollama · Qwen3 4B: requires a running Ollama service and the configured, digest-checked model. Download completion alone does not establish successful serving or evaluated quality.

A “verified” report has passed the implemented machine checks for its claims and evidence. Independent semantic review remains a separate task. Sixty authored deterministic cases and the Groq regression passed the recorded checks; these results are not guarantees for arbitrary questions.

Prepared showcase

The Cached showcase contains 36 frozen reports for twelve quality-selected matches: three reports per match, all for the home team and the same second-half comparison. Select Prepared report, inspect a claim, or choose Open this match.

In the local workspace these are explicitly labelled drafts awaiting human review. Public mode hides them until approval is recorded. The public-mode analyst has no live generation controls. Reports are bound to fingerprints and source/model versions so changed or stale content cannot silently inherit approval.

Search definitions

In the local analyst, search the methodology for phrases such as “field tilt” or “final third entries.” Search retrieves project definitions and limitations, not new match statistics. The local hybrid method uses a pinned encoder when available; the production image falls back to BM25. Read the method returned rather than assuming every environment uses the hybrid benchmark.

This section documents what was actually trained and measured, including unsuccessful hypotheses. Consult the sample size, data partition, selected model, calibration, intervals, ablations and provenance alongside any headline score.

9. Metric reference

MetricHow to read it
xGEstimated probability that a shot becomes a goal. A sum describes the modelled quality of recorded chances, not the actual score. Penalties are modelled separately.
Signed movement xTChange in the spatial threat value associated with observed movement/loss actions. Negative totals can occur. It is not a goal count.
Pass completionCompleted divided by attempted passes. A fraction of 0.75 means 75%; zero attempts produces unavailable, not 0%.
Final-third entries/minuteCompleted passes or carries crossing from x<80 to x≥80 on the 120×80 pitch, divided by elapsed window minutes.
Field tiltA team's share of both teams' completed passes ending in their attacking third. It is not possession time.
HHI concentrationSum of squared outgoing pass shares. Higher values indicate more concentration through fewer senders in that observed network.
Network strength / densityStrength summarizes pass counts; density measures observed directed links relative to possible links. Neither alone measures tactical quality.
Log loss / BrierProbability error measures; lower is better on comparable tasks and samples. Scores from different targets are not directly interchangeable.
Recall@5 / MRR@5Retrieval measures of whether relevant material appears in five results and how highly it ranks.
Silhouette / ARISilhouette describes cluster separation; ARI measures agreement between assignments. Neither establishes a real tactical cause.

10. Architecture and reproducibility

Flow: pinned StatsBomb files → checksum-checked ingestion → normalized database → offline experiments and stored predictions → FastAPI analytical endpoints → React/Vite interface and evidence views.

SQLite is used for the local research workspace; PostgreSQL is supported for deployment. SQLAlchemy and Alembic manage database access and schema evolution. Python implements the analytics. React displays returned measurements; it does not perform model training.

Source commit and file hashes establish which data was used. Frozen match splits establish the experiment boundaries. Model hashes, protocol files and aggregate reports establish what was fitted and evaluated. Evidence links lead back to event IDs and timestamps in the pinned upstream files.

Important folders: src/tactigraph/ for backend/analytics, frontend/src/ for UI, configs/ for protocols, experiments/ for aggregate results, docs/ for model cards and methods, and tests/ for synthetic checks. Private local data lives under data/, models under artifacts/, and review/verification outputs under output/.

The production Docker image excludes databases, raw files, private review packets, credentials and ML model artifacts. It reads precomputed results from its database. The deployment preparation included transfer of twelve selected matches and a successful PostgreSQL backup/restore rehearsal.

11. Limitations and interpretation

  • Historical WSL event data does not establish performance on other leagues, men's football or future seasons.
  • Events are not continuous tracking. Unobserved defensive shape, movement and alternatives remain unobserved.
  • Small windows, game state, opponents and dismissals can influence every comparison.
  • Player-removal results are fixed-graph sensitivity, not causal football counterfactuals.
  • Style labels describe measured passing patterns; clusters are not natural tactical categories proven by the model.
  • Model probabilities have uncertainty and can be wrong. No betting or match-result guarantee is supported.
  • Human review of the cached reports and publication terms is still pending.
  • The application is not a permanently hosted service. Local availability depends on a running server; public hosting has not been set up.

Data is provided by StatsBomb. The code licence does not grant ownership or unrestricted redistribution of upstream data. Before public use, review the official attribution instructions and data agreement.

12. Maintenance and next steps

Routine use

Use the launcher rather than rerunning ingestion or model development every time. Keep the database and model artifacts. Back up private data before upgrades, and do not delete evaluation locks to repeat model selection against a previously inspected test.

Useful troubleshooting

  • Page loads but requests fail: check the server health link, run the launcher and refresh.
  • Server cannot start: inspect the error log for a port conflict, missing environment, missing data or an application error.
  • Invalid comparison: confirm the selected half, period-local minutes, chronological order and non-overlapping bounds.
  • Model unavailable: distinguish a missing stored analytical model from a missing optional language-model service.
  • Report hidden in public mode: review approval is pending or its source/model changed; do not bypass that label.
  • Slow first methodology search: a local encoder may be loading. The production fallback has different behaviour and measured quality.

Before a genuine public release

  1. Complete an independent review of output/release-review/index.html and its 36 reports; record approvals against the exact fingerprints.
  2. Complete publication/attribution checks.
  3. Create a code-only repository and hosting account, choose a budget and validate the hosting configuration.
  4. Import the reviewed database into private PostgreSQL and deploy the web image.
  5. Verify live readiness, citations, accessibility, load behaviour, backups and actual costs.

The detailed deployment procedure is in docs/public-release.md. Hosting was deliberately deferred at the user's request. No cloud resources or hosting bill were created during preparation.

Potential future improvements

Useful additions could include a French interface, more onboarding, easier exports for analysts, broader independent evaluation, improved retrieval and monitoring for a hosted service. These are possible extensions, not claims that they already exist or requirements to add complexity before the current workflows are reviewed.
